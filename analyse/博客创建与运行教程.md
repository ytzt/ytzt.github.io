# YTZT 博客创建与发布教程

本文说明这个仓库的运行架构，以及如何新增一篇包含公式和图片的 Markdown 文章。当前仓库只保留一篇“轨迹规划系统理解”示例文章，后续可直接复制它作为自己的文章模板。

## 一、项目运行架构

这是一个由 GitHub Pages 构建的 **Jekyll 静态博客**，不需要后端服务：

```text
_posts/*.md                 文章源文件（YAML front matter + Markdown）
        │
        ▼
Jekyll + kramdown + Rouge    Markdown、代码高亮、Liquid 模板处理
        │
        ├── _layouts/post.html   文章详情页布局
        ├── _layouts/page.html   首页布局
        ├── _includes/*.html     导航、页头、侧栏、MathJax 等组件
        └── _config.yml          站点配置、分页、永久链接、插件
        │
        ▼
_site/                       静态 HTML/CSS/JS（GitHub Pages 发布）
```

- `index.html` 使用 `paginator.posts` 遍历文章，所以首页显示什么由 `_posts` 中的文章及其 `published` 状态决定。
- 文件名使用 `YYYY-MM-DD-title.md`，Jekyll 会按照日期生成 URL。当前配置 `permalink: pretty`，示例文章的地址是 `/2026/09/20/trajectory-planning-system/`。
- `_layouts/post.html` 输出文章正文；当文章 front matter 写入 `mathjax: true` 时，会加载 `_includes/mathjax_support.html`，浏览器再把 TeX 公式转换成 SVG。
- `img/`、`css/`、`js/` 和 `fonts/` 是直接复制到发布站点的静态资源。图片不会经过 Markdown 编译，必须确保 URL 和大小写正确。
- `CNAME` 保存自定义域名（如果使用 `用户名.github.io`，通常不需要改它）。

## 二、准备 GitHub Pages 仓库

1. 将仓库命名为 `<用户名>.github.io`，并把代码推送到默认分支（通常是 `main` 或 `master`）。
2. 在 GitHub 的 **Settings → Pages** 中选择 **Deploy from a branch**，选择默认分支和 `/ (root)` 目录。
3. 如果使用自定义域名，把域名写入 `CNAME`，并为域名配置 DNS。GitHub Pages 构建完成后，访问 `https://<用户名>.github.io/`。
4. 这个仓库的 `Gemfile` 固定了 Jekyll 4、`jekyll-paginate` 和 `webrick`。本地预览需要 Ruby 和 Bundler。

```bash
bundle install
bundle exec jekyll serve --future
# 浏览器打开 http://localhost:4000/
```

`--future` 会显示日期晚于当前日期的文章；写作时可保留，发布时 GitHub Pages 也会按配置中的 `future: true` 构建。

## 三、创建自己的文章

复制示例文章，然后修改文件名和开头的 front matter：

```bash
cp _posts/2026-09-20-trajectory-planning-system.md \
   _posts/2026-09-21-my-first-post.md
```

最小可用的 front matter 如下：

```yaml
---
layout: post
title: "我的第一篇文章"
subtitle: "可选的副标题"
date: 2026-09-21
author: "你的名字"
header-img: "img/post-bg-rwd.jpg"
tags:
  - 笔记
mathjax: true
---
```

注意：

- `layout: post` 让文章使用博客详情页；不要删除两侧的 `---`。
- `date` 影响排序和 URL；文件名日期应与它保持一致。
- `published: false` 会让文章不参与发布，适合草稿。
- `header-img` 是文章顶部背景图，路径相对于站点根目录，文件应放在 `img/` 下。
- 首页只显示正文前一段的纯文本摘要；点击标题才会打开完整文章。

## 四、在 Markdown 中写公式

示例文章已打开 MathJax：

```yaml
mathjax: true
```

行内公式用单个美元符号包裹，例如 `$s(t)=s_0+vt$`。独立公式用两个美元符号：

```markdown
$$
J = \int_0^T \left\|u(t)\right\|^2 dt
$$
```

仓库的 MathJax 配置支持 TeX/AMS 语法和自动编号。公式只在浏览器加载 MathJax 后渲染，因此本地离线打开生成的 HTML 时可能暂时看不到公式；部署到 GitHub Pages 后会从 CDN 加载脚本。

## 五、添加图片和图表

把图片放到文章专属目录，例如 `img/in-post/my-post/diagram.png`，再在 Markdown 中引用：

```markdown
![系统结构图](/img/in-post/my-post/diagram.png)
```

推荐使用有意义的 `alt` 文本，并提交图片文件本身。SVG、PNG、JPEG 都可以；文件名尽量使用英文、数字和短横线，避免空格和中文路径。若站点未来设置了非空 `baseurl`，可将图片写成 Liquid 形式以兼容子路径：

```liquid
![系统结构图]({{ site.baseurl }}/img/in-post/my-post/diagram.png)
```

示例文章使用了 `img/in-post/trajectory-planning/pipeline.svg`，可以作为图片引用和 SVG 绘图的参考。

## 六、提交、检查和发布

```bash
git add _posts/ img/ analyse/
git commit -m "Add my blog post"
git push origin main
```

推送后在仓库的 **Actions** 中查看 Pages 构建任务。若页面没有文章或打开 404，按以下顺序检查：

1. 文件是否位于 `_posts/`，文件名是否以日期开头并以 `.md` 或 `.markdown` 结尾；
2. front matter 是否从文件第一行开始，YAML 缩进是否正确；
3. 是否误写了 `published: false`，或日期晚于当前时间且没有启用 `future`；
4. 图片路径是否从 `/img/` 开始、文件名大小写是否完全一致；
5. 文章 URL 是否使用了日期目录，且没有把本地 `localhost:4000` 写进链接。

以后新增文章只需要提交 Markdown 和它引用的图片。Jekyll 会在 GitHub Pages 构建时自动把它加入首页，`index.html` 不需要手工修改。
